05 / Arsitektur Firmware C++ · Contoh Pola Inferensi On-Device pada ESP32

Pola Kodingan Inferensi di Mikrokontroler

// Pola: Windowing Sinyal 50 Hz → Eksekusi Inferensi run_classifier → Aksi Aktuator Lokal
// Catatan: Library "my_tinyml_model_inferencing.h" merupakan hasil ekspor dari Edge Impulse.

#include <Wire.h>
#include <MPU6050.h>
#include "my_tinyml_model_inferencing.h"

float sensor_buffer[EI_CLASSIFIER_DSP_INPUT_FRAME_SIZE];
MPU6050 mpu;

void setup() {
  Serial.begin(115200);
  Wire.begin();
  mpu.initialize();
}

void loop() {
  // 1. Mengisi ring buffer data sensor (Sampling Rate 50 Hz = interval 20 ms)
  for (size_t i = 0; i < EI_CLASSIFIER_DSP_INPUT_FRAME_SIZE; i += 3) {
    int16_t ax, ay, az;
    mpu.getAcceleration(&ax, &ay, &az);
    sensor_buffer[i]     = (float)ax / 16384.0f * 9.81f; // Normalisasi ke satuan m/s^2
    sensor_buffer[i + 1] = (float)ay / 16384.0f * 9.81f;
    sensor_buffer[i + 2] = (float)az / 16384.0f * 9.81f;
    delay(20); // Gunakan timer interrupt untuk implementasi produksi
  }

  // 2. Membungkus buffer ke format sinyal Edge Impulse
  signal_t signal;
  numpy::signal_from_buffer(sensor_buffer, EI_CLASSIFIER_DSP_INPUT_FRAME_SIZE, &signal);

  // 3. Menjalankan inferensi model kuantisasi INT8 on-device (< 15 ms)
  ei_impulse_result_t result = { 0 };
  run_classifier(&signal, &result, false);

  // 4. Pengambilan keputusan otomatis secara lokal di mikrokontroler
  if (result.classification[1].value > 0.85f) {
    // Terdeteksi kondisi anomali > 85%: Picu relay, buzzer, atau kirim alert via LoRa
    Serial.println("PERINGATAN: Kerusakan / Anomali Terdeteksi!");
  }
}

API run_classifier mengikuti standar Edge Impulse. Skala 16384 LSB/g merujuk datasheet resmi MPU-6050. Runtime TinyML: TFLM.

07 / Panduan Mengatasi Masalah (Troubleshooting & Debugging Lapangan)

Solusi 4 Gejala Error yang Paling Sering Terjadi

1. Error: AllocateTensors() failed / Kehabisan Memori RAM

Penyebab: Alokasi tensor arena di SRAM terlalu kecil untuk menampung layer model.
Solusi: Perbesar nilai kTensorArenaSize (misal dari 10KB menjadi 25KB), atau kurangi resolusi input / jumlah neuron pada model. Konsep arsitektur arena: TFLM.

2. Akurasi di PC 95%, tetapi di ESP32 Sering Salah Tebak

Penyebab: Perbedaan frekuensi sampling (Sampling Rate Mismatch) antara saat merekam data latih dengan pembacaan sensor nyata.
Solusi: Jangan mengandalkan delay() biasa; gunakan hardware timer interrupt agar frekuensi sampling tepat konstan (misal: stabil di 50 Hz). Kuantisasi INT8 sendiri umumnya hanya menyumbang penurunan akurasi sangat kecil.

3. Mikrokontroler Mendadak Restart / Brownout Saat Sensor Aktif

Penyebab: Lonjakan tarikan arus sesaat saat sensor atau radio aktif menyebabkan tegangan 3.3V turun mendadak.
Solusi: Pasang kapasitor decoupling 100 µF (elektrolit) dan 0.1 µF (keramik) secara paralel di antara pin VCC dan GND sensor.

4. Daya Baterai Cepat Habis (< 2 Hari Operasional)

Penyebab: Modul Wi-Fi dan CPU mikrokontroler terus aktif tanpa manajemen daya.
Solusi: Aktifkan mode Deep Sleep ESP32 dan gunakan interupsi eksternal (ext0 wake-up) dari sensor getaran agar mikrokontroler hanya bangun saat ada peristiwa penting. Rujukan API: Espressif Sleep Modes.
